# 五部 iPad 獨立人臉觸發 PWA 設計

日期：2026-09-02
狀態：已確認，待實作

## 目標

建立一個以 GitHub Pages 發佈的靜態 PWA。五部 iPad 掃描同一個 QR Code 後，各自在本機進行人臉偵測、粵語播放、音樂播放、設定保存及觸發統計，彼此不連線、不同步。

## 非目標

- 不顯示或分配裝置編號。
- 不使用帳戶、資料庫、WebSocket 或中央控制台。
- 不上傳、錄製或保存相機影像。
- 不建立原生 iOS App。
- 不加入普通話或其他語言。

## 部署方式

- 程式放在 repo 的 `face-trigger/` 目錄，與現有遊戲分開。
- GitHub Pages workflow 只把 `face-trigger/` 發佈為 Pages 網站根目錄。
- 預期固定網址為 `https://fox0310.github.io/steam-game/`；實際啟用 Pages 後再核對。
- 只產生一個 QR Code，永久指向固定網址，不帶裝置參數。
- GitHub Pages 只提供靜態檔案。所有偵測與播放邏輯在 iPad 瀏覽器執行。

## 最小技術架構

不使用前端框架或後端。主要檔案：

- `index.html`：介面結構及 PWA metadata。
- `styles.css`：高對比、iPad 響應式介面。
- `app.js`：相機、偵測狀態、音訊、設定及 UI 協調。
- `trigger-state.js`：可獨立測試的人臉觸發狀態機。
- `service-worker.js`：離線快取與版本更新。
- `manifest.webmanifest`：加入 iPad 主畫面的 PWA 資訊。
- `assets/`：圖示、MediaPipe runtime、WASM 及模型。
- `self-check.mjs`：狀態機與設定規則的最小自動檢查。

不使用 Tailwind CDN、Font Awesome CDN 或執行時遠端模型。樣式、圖示與 MediaPipe 所需檔案全部隨網站發佈，確保首次成功載入後可離線重開。

## 使用流程

1. 使用者掃描同一個 QR Code，在 Safari 開啟 GitHub Pages 網址。
2. 首頁顯示大型「啟動感應」按鈕。
3. 使用者點擊按鈕後，網頁請求相機權限並解鎖 iPad 音訊。
4. 系統啟動前置鏡頭及 MediaPipe 單人臉偵測。
5. 人臉連續出現至少 500 毫秒後，觸發目前選取的粵語或音樂內容一次。
6. 同一張臉持續留在畫面時不會再次觸發。
7. 畫面連續 2 秒沒有偵測到人臉後，系統重新進入可觸發狀態。
8. 下一次人臉進入後可再次播放。

## 觸發狀態機

狀態：

- `idle`：相機未啟動。
- `ready`：等待人臉。
- `arming`：人臉已出現，累計 500 毫秒穩定時間。
- `playing`：正在播放；忽略新觸發。
- `wait-for-exit`：播放結束但人臉仍存在，等待離開。
- `paused`：使用者暫停感應；不處理人臉結果。
- `error`：相機、模型或音訊無法啟動。

重要規則：

- `arming` 期間若人臉消失，立即回到 `ready`。
- 播放期間仍記錄人臉是否離開；播放結束時若人臉仍存在，進入 `wait-for-exit`。
- 播放結束時若已連續無臉 2 秒，可直接回到 `ready`。
- `wait-for-exit` 只有在連續 2 秒沒有臉後才回到 `ready`。
- 暫停感應會停止播放並回到暫停狀態；恢復時重新要求完整離開週期，避免立即誤觸。

## 播放內容

提供五個選項：

1. 早晨：`zh-HK` 系統語音朗讀「早晨」。
2. 午安：`zh-HK` 系統語音朗讀「午安」。
3. 你好：`zh-HK` 系統語音朗讀「你好」。
4. G班：`zh-HK` 系統語音朗讀「G班」。
5. 輕快音樂：Web Audio 即時合成的原創電子旋律，不朗讀語音。

語音播放前可保留短提示音。輕快音樂預設播放 7 秒，並跟隨使用者設定的播放時長；旋律需要較長時會循環，到時立即停止。所有音訊受同一音量控制。

只選用 `zh-HK` 語音。若裝置沒有可用的粵語聲音，不自動改用普通話；介面提示使用者在 iPad 設定中安裝或啟用粵語聲音。音樂選項仍可使用。

## 介面

- 相機畫面保持最大可視區域，控制項使用 DOM 疊層。
- 保留狀態徽章、人臉標記、播放倒數及簡單音樂律動提示。
- 保留五個內容快捷按鈕、音量、播放時長、前後鏡頭及視覺效果設定。
- 保留手動觸發、暫停／恢復感應及中斷播放。
- 移除裝置 ID、五個專屬網址及五機 QR 網格。
- 提供一個「分享 QR」按鈕，顯示固定 GitHub Pages 網址的單一 QR Code。
- 首次畫面清楚說明需要按一下才能啟動相機及聲音。

## 無障礙與 iPad 適配

- 主要觸控目標至少 44×44 CSS pixels。
- 使用高對比文字、圖示加文字標籤，不單靠顏色表示狀態。
- 所有按鈕提供可讀名稱、明顯焦點樣式及按下狀態。
- 支援直向與橫向；安全區使用 `env(safe-area-inset-*)`。
- 非必要動畫遵從 `prefers-reduced-motion`。
- 避免阻止 VoiceOver 所需的標準觸控行為。

## 本機資料與私隱

每部 iPad 使用自己的瀏覽器儲存空間：

- `localStorage` 保存內容選擇、音量、播放時長、鏡頭方向、視覺效果及累計觸發次數。
- 設定以 schema version 包裝；版本不相容時安全回復預設值。
- 相機 frame 只傳入裝置內 MediaPipe runtime，處理後即丟棄。
- 不發送分析資料、影像、裝置識別或觸發紀錄。

因此，同一 QR Code 與同一網址不會令五部 iPad 共用狀態。

## 離線與更新

- 第一次使用必須連線，讓 Safari 下載完整程式、模型及 PWA 快取。
- Service Worker 採用版本化 app-shell cache。
- 已快取版本在沒有網絡時可啟動及運行。
- 有網絡時在背景取得新版；新版本準備完成後提示使用者重新載入，不在活動中強制刷新。
- 若首次下載未完成，不宣稱已可離線；介面顯示「離線內容已準備」後才算完成。

## 錯誤處理

- 非 HTTPS 或不支援相機：停止啟動並顯示明確原因。
- 相機權限被拒：顯示 Safari／iPad 設定的重開權限指引。
- 找不到鏡頭：保留手動音訊測試，但停用自動偵測。
- MediaPipe 模型載入失敗：提供重試按鈕；有舊快取時繼續使用舊版。
- `zh-HK` 聲音不可用：不改讀普通話，顯示粵語聲音提示。
- Web Audio 啟動失敗：提示再次點擊啟動或檢查靜音／音量。
- Wake Lock 不支援或被系統收回：顯示非阻斷提示；回到前景時重新申請。

## 測試策略

### 自動檢查

- 人臉需穩定 500 毫秒才觸發。
- 短暫誤判不觸發。
- 人臉持續存在不重播。
- 人臉離開不足 2 秒不重置。
- 離開滿 2 秒後可再次觸發。
- 設定驗證及 schema version 回復預設值。

### 瀏覽器檢查

- Playwright 模擬偵測結果，驗證主要按鈕、狀態文字、設定保存及 QR 內容。
- 驗證窄屏、iPad 直向及橫向版面沒有關鍵控制被遮擋。
- 驗證 Service Worker 快取清單完整，第二次載入可在離線模式開啟。

### 實體 iPad 驗收

五部 iPad 均需逐一驗證：

- 同一 QR Code 可進入同一網址。
- 每部機可獨立授權並使用前置鏡頭。
- 五部同時運行時互不影響。
- 粵語聲音、輕快音樂、音量及停止按鈕正常。
- 留在鏡頭前不重播；離開 2 秒再進入才重播。
- 加入主畫面後可啟動。
- 完成首次快取後，在飛行模式仍可啟動偵測及播放。

桌面自動測試不能取代實體 iPad 的 Safari、相機權限、系統語音及 PWA 驗收。

## 驗收條件

- 一個固定 QR Code 可供五部 iPad 使用。
- 所有 iPad 使用相同程式，但沒有共享狀態。
- 不顯示裝置編號。
- 人臉穩定 500 毫秒觸發一次，離開 2 秒後才重新準備。
- 四個粵語選項及一個原創輕快音樂選項可用。
- 相機影像不離開裝置。
- 首次成功快取後可離線運行。
- GitHub Pages HTTPS 版本及五部實體 iPad 驗收通過。
